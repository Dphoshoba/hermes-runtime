## 5. Current Preparation Implementation

Traced through `enterprise/services/preparation.py` (267 lines). The pipeline:

1. **Gate:** reads `repository.metadata_json["preparation_allowed"]` (line 152-156)
2. **Resolve target:** reads `metadata_json["local_path"]` (line 158-161)
3. **Snapshot target:** SHA-256 hashes of all files (line 163, function at lines 60-68)
4. **Create workspace:** `shutil.copytree(target_repo, workspace)` (line 172)
5. **Git baseline:** `git init` + `git commit` in workspace (lines 177-193)
6. **Apply change:** `_apply_candidate_change()` — `str.replace()` on `src/config.py` (line 195, function at lines 76-95)
7. **Compute diff:** `difflib.unified_diff()` comparing workspace vs original (line 213, function at lines 98-110)
8. **Run validation:** `subprocess.run([sys.executable, "-m", "pytest", "-q"])` in workspace (line 214, function at lines 113-135)
9. **Verify target:** `_target_unchanged()` — re-hashes target, compares to snapshot (line 217, function at lines 71-73)
10. **Record results:** sets `prepared.status = "PREPARED"` if validation passed AND target unchanged (line 219-267)

Every step is real filesystem execution. No step is simulated or stubbed.
